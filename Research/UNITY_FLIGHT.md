# Unity flight research mode

Open Assets/FlightLab.unity, enter Play, then select **Fruit Fly → Research → Start Trained Flight Backend**. Backend loading takes several seconds. Click the Game view to focus it. P pauses/resumes simulation; Backspace replays the reference episode; mouse/right stick looks independently; R recenters; Escape releases the mouse. Stop with the research backend menu, or leave Play. Only one research backend should run at a time.

The physical walker uses the published trained policy, measured wing pattern, and recorded trajectory 1. Its 85 compiled visual meshes are exported separately from the passive body resource. Reference ghost geometry is excluded. Units convert from centimeters to meters, then to the Unity display scale. The mounted rider and gripping legs follow the actual thorax body's position and orientation. The rider adds one third of the fly's mass (0.328207 mg) as a rigid spherical inertia approximation at the thorax. Grip is rigid, with no leg-grip muscle model.

The ordinary trained backend has no active connectome control. **Start Experimental Neural Flight Backend** enables an explicitly unvalidated full-connectome loop with body feedback, synthetic direct DNg02 excitation, actual spike readouts, and bounded wing-yaw residuals over the trained stabilizer. This is not a biological sensory model or calibrated motor decoder. Replay resets both physical and neural states. Combat is not connected to this scientific body. See FLIGHT_PROGRESS.md for actual results and limits.

The reference episode ends and holds its final pose; replay resets the environment and starts a new stream session. Actions use the policy distribution's mean, clipped to the task limits before application. Physics updates every 50 microseconds and control every 200 microseconds. Each visible update advances up to 15 milliseconds of simulation, so wing motion is sampled rather than a faithful high-speed recording. Inference is substantially slower than real time on this environment.

flight-stream-evaluation.json records checks for finite geometry and thorax poses, advancing motion, pause holding the exact pose/time, resume, replay session reset, and reference completion at 227 milliseconds with zero action clips. The standalone C# API compilation passed with zero warnings/errors. Live Unity testing passed and is recorded separately in unity-flight-evaluation.json. Observed rider attachment, changing flight poses, pause/resume/replay, the final reference-completed label and clip counter. Leaving Play released both backend and viewer ports; the Editor is left stopped on FlightLab.

The checkpoint and recorded-flight assets remain in the local work/research/flight-assets directory under the authors' GPL-3.0-or-later dataset terms. FlyBody code/meshes retain their Apache-2.0 attribution. See TRAINED_FLIGHT.md and flight-assets.json for source, checksums, compatibility adaptation, and short-controller-test limits.
